## 1. 背景と目的

埼玉大学の学園祭「むつめ祭」の **2027年度** 開催回で、同人誌即売会『コミックさいたま』を開催するための準備会の公式サイト。開催日は未定。

当初は2026年度（2026/11/28〜30）の開催を予定していたが、2027年度に変更した。開催まで約1年の準備期間があるため、サイトの役割は時期によって次のように移っていく。

| 時期 | サイトの主な役割 |
|---|---|
| 現在〜募集要項の公開まで | 準備会の紹介、**スタッフ募集**、**最新情報を受け取る人を増やす**（Discord・X・メーリングリスト） |
| 募集要項の公開〜申込締切 | **サークル参加の申込窓口**（募集要項・日程・申込フォーム・締切の明示） |
| 申込締切〜開催 | **来場告知**（日時・会場・アクセス・注意事項・サークル一覧） |
| 開催当日 | 当日のお知らせ（混雑・頒布終了など）の即時発信 |
| 開催後 | 開催報告・アンケート、次回へのアーカイブ |

全期間を通じて、団体の信頼性を示す（主宰挨拶・問い合わせ先・個人情報の取り扱い）。

## 2. 利用者

| 利用者 | 知りたいこと / やりたいこと | 主に見るページ |
|---|---|---|
| サークル参加希望者 | 参加資格、参加費、スペース、搬入出、頒布物の規定、申込締切 | 参加詳細 → 申込フォーム |

| 準備会メンバー（更新者） | 情報を早く・間違いなく更新したい | リポジトリ（README） |

## 3. フェーズ計画（2027年度開催）

開催日が未定のため、期限は「開催日からの逆算」で定め、開催日が決まった時点で日付に置き換える。

| フェーズ | 目安 | ゴール | 状態 |

## 4. 機能要件

### 4.1 共通

| ID | 要件 | 状態 |
|---|---|---|
| F-C1 | ヘッダー・フッター・`<head>` を1か所で管理する | ✅ `BaseLayout` / `Header` / `Footer` |
| F-C2 | 団体名・連絡先・SNS・イベント情報を設定ファイル1か所で管理する | ✅ `src/data/site.ts` |
| F-C3 | スマホはハンバーガーメニュー、PC は横並びナビ。キーボード操作可能 | ✅ |
| F-C4 | ナビで現在のページを示す | ✅ `aria-current` |
| F-C5 | 存在しないURLでサイト独自の404ページを表示 | ✅ |
| F-C6 | 最新情報を受け取る手段（Discord / X / メーリングリスト）を案内する | ✅ Discord は招待URL設定待ち（#12） |
| F-C7 | 全ページから個人情報の取り扱いへリンクする | 下書き済み・未公開（#13） |

### 4.2 ページ

| ページ | 掲載内容 | 状態 |
|---|---|---|
| **トップ** `/` | 告知欄（ロゴ・開催時期/日程・会場・ボタン）、申込状況の帯、お知らせ、イベント概要、開催スケジュール、最新情報を受け取る、参加方式、Q&A、主宰挨拶 | ✅（日程は未定表示） |
| **参加詳細** `/pages/services.html` | 募集要項（資格・スペース・参加費・委託手数料）、日程、申込導線、頒布物ガイドライン、FAQ、最新情報を受け取る | 一部（募集要項は #14） |
| **スタッフ募集** `/pages/recruit.html` | 募集要項、活動内容、応募フォーム、個人情報の取り扱いへのリンク | ✅（ポリシーへのリンクは #13 公開時） |
| **お問い合わせ** `/pages/contact.html` | メール、X、メンバー | ✅ |
| **個人情報の取り扱い** `/pages/policy.html` | 取得する情報、利用目的、管理・保管期間、第三者提供、外部サービス、開示等の窓口 | 下書き（`npm run dev` でのみ表示、#13） |
| **来場案内** `/pages/visit.html` | 日時・会場・入場料・入構可否・アクセス・注意事項・サークル一覧 | 未作成（#15） |

### 4.3 申込状況の切り替え

`src/data/site.ts` の `event.entry.status` で、トップの告知帯と告知欄のボタンを切り替える。

| status | 表示 |
|---|---|
| `upcoming` | 募集要項は準備中＋最新情報を受け取る案内（現在） |
| `open` | 受付中・締切日・残り日数（閲覧時に計算）＋申込ボタン |
| `closed` | 受付終了 |

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| 対応環境 | iOS Safari / Android Chrome / PC 主要ブラウザの最新版。スマホ閲覧を主とする |
| 表示速度 | 静的HTML・クライアントJSは最小限。画像は WebP に最適化（`astro:assets`） |
| アクセシビリティ | 文字色のコントラスト 4.5:1 以上、キーボード操作、`alt`・`aria` 属性 |
| SEO / SNS | ページごとの `title`・`description`・`canonical`・OGP（1200×630）、sitemap |
| プライバシー | 個人情報はサイトに保持しない（フォーム側）。取り扱いを明示する（#13） |
| 保守性 | 文言・お知らせ・日程・連絡先は GitHub の画面だけで更新できる |
| 品質 | PR ごとに型チェック・ビルド・リンク切れチェックを実行し、失敗したらマージ不可 |

## 6. 技術構成

| 項目 | 内容 |
|---|---|
| フレームワーク | Astro 7（静的サイト生成） |
| ホスティング | GitHub Pages（`.github/workflows/deploy.yml`、`withastro/action` → `actions/deploy-pages`） |
| CI 実行環境 | `ubuntu-24.04` に固定 |
| URL | `site: https://comic-saitama.github.io`、`base: /web_comisai`、`build.format: 'file'`（`/pages/*.html` を維持） |
| 設定・データ | `src/data/site.ts`（団体・連絡先・SNS・GA・イベント・フォーム）、`src/content/news/*.md`（お知らせ） |
| 下書き | `src/drafts/` に置き、`src/pages/pages/[draft].astro` から開発サーバーでのみ表示 |
| 品質チェック | `astro check`、`scripts/check-links.mjs`（リンク・アンカー切れ） |
| 依存更新 | Dependabot（npm 毎週、GitHub Actions 毎月） |
| 改行コード | `.gitattributes` で LF に統一 |

## 7. 運用

| 項目 | 内容 |
|---|---|
| 更新フロー | ブランチ → PR → CI 成功 → `main` にマージで自動公開（README 参照） |
| ブランチ保護 | `main` への直接 push 不可、CI（build）成功が必須、管理者にも適用。承認は推奨（必須ではない） |
| 当日運用 | 開催日は GitHub の画面からお知らせを追加できる担当者を置く。サイト障害時は X・Discord を一次告知手段とする |
| 担当者 | 未定（README に記載する） |

## 8. 受け入れ基準（P2：募集要項の公開時点）

- [ ] 開催日・会場がトップの告知欄に表示されている（`event.dates` / `event.venue`）
- [ ] 参加詳細ページから2タップ以内でサークル申込フォームに到達できる
- [ ] 告知帯が「受付中」になり、締切日と残り日数が表示される
- [ ] 個人情報の取り扱いページが公開され、全ページ・全フォームの近くからリンクされている
- [ ] 最新情報を受け取る手段（Discord を含む）が表示されている
- [ ] CI（型チェック・ビルド・リンクチェック）が成功している
